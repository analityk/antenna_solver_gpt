# 3. PML semantics audit

**NOT A PROBLEM — brak off-by-one.** Dla M linii i `PML_N`:

- dolny absorber: indeksy linii `0…N`, czyli N komórek;
- górny: `M-1-N…M-1`, również N komórek;
- `BC size = N`; `SetRange()` przechowuje N+1 linii. To różne wielkości.

Python przekazuje N do `Set_BC_PML()`, operator dostaje tę samą wartość. `CalcGradingKappa()` wyznacza szerokości z `line[N]-line[0]` oraz `line[M-1]-line[M-1-N]`. Przesunięcie pól Yee nie dodaje komórki. Obecne indeksy `axis[N]`, `axis[-N-1]` są prawidłowe. Nie kopiować dodatkowego odsunięcia sond NF2FF jako rozmiaru PML.

Źródła openEMS `6761a36`: [Python BC](https://github.com/thliebig/openEMS/blob/6761a36e28567129d833de2ae7df4fb102dc5ceb/python/openEMS/openEMS.pyx), [przekazanie BC size](https://github.com/thliebig/openEMS/blob/6761a36e28567129d833de2ae7df4fb102dc5ceb/openems.cpp), [Create_UPML/SetRange/CalcGradingKappa](https://github.com/thliebig/openEMS/blob/6761a36e28567129d833de2ae7df4fb102dc5ceb/FDTD/extensions/operator_ext_upml.cpp).

# 4. Domain and resolution audit

- **NOT A PROBLEM — clearance/Z.** Odstęp `air_padding_wavelengths*C0/min(result_frequency_hz)` kończy się na początku PML. Grubości absorbera nie wliczać. 0,25 realizuje projektowy odstęp λ/4; wymaga późniejszej kontroli większą domeną ([BC](https://docs.openems.de/en/latest/concepts/bc.html)). - **NOT A PROBLEM — Cartesian cost.** Lokalne ograniczenia dotyczą przedziałów osi, nie lokalnych komórek 3D: drobne X/Y rozciągają się na całe płaszczyzny. Iloczyn liczby przedziałów uwzględnia ten koszt i PML. Budżet osi `floor(max_cells/product(other_shapes))-2*N` jest poprawny: pozostałe rozmiary są dolnymi ograniczeniami i mogą tylko rosnąć. Kontrole przed alokacją i po PML wystarczają jako limit liczby komórek v0; nie gwarantują limitu RAM ani czasu FDTD, zależnego też od najmniejszego kroku.

Nie jest to stosunek wymiarów komórki X:Y:Z. Wszystkie współrzędne są w metrach.
